# testslop

Finds Rust tests to delete, merge into a table, or give a shared fixture. Every hit is a suggestion
for an agent or a human to review; nothing is auto-applied.

## Usage

```bash
cargo build --release
testslop scan <repo>                                             # static checks over every test
testslop cov <repo> -p <package> [-- --features x]               # per-test coverage of one package's lib tests
testslop scan <repo> --json                                      # every hit, sorted, as JSON
testslop scan <repo> --only parametrizable-tests --limit 50
testslop scan <repo> --write-baseline .testslop.json             # accept every current hit
testslop scan <repo> --baseline .testslop.json                   # report only new hits (exit 1 if any)
```

Exit codes: 0 no hits, 1 hits, 2 error.

`cov` builds `<package>`'s lib test binary into `<repo>/target/testslop`, instrumenting only that crate
(testslop acts as its own `RUSTC_WORKSPACE_WRAPPER`), runs each non-ignored test alone, and diffs
the production regions each one executes. It needs the `llvm-tools` rustup component of the repo's toolchain.
Production code is the package's `src/` minus `#[cfg(test)]` modules, test functions, and `test_util(s)` files.

## Lints

| Lint | Source | Means |
|---|---|---|
| `parametrizable_tests` | scan | same-file tests whose bodies differ in at most 8 tokens: one table |
| `missing_fixture` | scan | a statement prefix that 3 or more tests in a file open with |
| `copy_paste_assert_block` | scan | a block repeated inside one test: a loop |
| `no_assertion_test` | scan | no assert, unwrap, `?` or panic in the body (often a thin wrapper around an assert helper, which is a table candidate) |
| `tautological_assert` | scan | `assert_eq!(x, x)` |
| `field_by_field_assert` | scan | three or more `assert_eq!(v.f, ..)` in a row |
| `manual_assert_matches` | scan | a `match` or `let .. else` that only panics on a miss |
| `no_prod_coverage` | cov | runs no production code: tests generated code (derives, `thiserror`, `sol!`), upstream crates, or test helpers |
| `duplicate_coverage` | cov | covers exactly the regions of another test |
| `subsumed_coverage` | cov | covers a strict subset of another test's regions (the smallest such test is named) |

The coverage lints are hazy. They show where a test runs, not what it asserts. Two tests can cover the same
regions and check different values, such as a saturating clamp, a boundary or a rounding direction. Review the
assertions before deleting, or confirm with a mutation run. Constant and layout guards (selector and
storage-layout snapshots) show up as `no_prod_coverage`, but they are intentional.

Tests generated by `macro_rules!` can't be mapped back to source, so `cov` counts them and skips them.
`scan` does see `#[test] fn` items written inside macros such as `proptest!`.

## Known gaps

- Syntax only: no types, so derived-impl tests are found only by `cov`.
- Clone clusters need identical token shapes; reordered statements are missed.
- No mutation testing yet; it is the confirmation step `cov` hits need before deletion.
